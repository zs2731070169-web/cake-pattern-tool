# pattern-tool 部署文档

> 适用版本：MVP（全本地图像处理，无 GPU 依赖）。
> 部署形态：单机 uvicorn（:8200，worker=1）+ Nginx 反代 HTTPS，单实例即可承接目标负载。
> 依据：《修图工具最小技术方案.md》6 节（单写者）、7 章与 7.1 节（部署与选型硬约束）。

## 1. 架构与端口

```
用户浏览器/手机
   │ HTTPS 443
   ▼
Nginx（反代：缓冲上传 + 限流 + 证书）
   │ HTTP 127.0.0.1:8200
   ▼
pt-web 单体（FastAPI :8200，worker=1）
   ├── /api/*   业务接口（建批 / 轮询 / 下载 / meta）
   ├── /        静态前端（web/index.html + app.js + vendor/cropperjs）
   └── data/    SQLite（pattern_tool.db）+ 批次图片（TTL 24h 自动清理）
```

- **worker 必须为 1**：SQLite 单写者前提（技术方案 6 节），禁止 `--workers N` 多进程。
- 前端与 API 同进程同源，无需单独部署静态站点。

## 2. 环境要求

| 项 | 要求 | 说明 |
|---|---|---|
| 操作系统 | Linux x86_64 / arm64 | 无 GUI 依赖（opencv 用 headless 包） |
| Python | 3.11 或 3.12 | 3.13+ 的 opencv/rapidocr 轮子未验证，3.10- 不再支持 |
| 磁盘 | ≥ 50GB | 瞬时驻留 12–24GB，TTL 24h 兜底；水位 > 70% 告警 |
| 内存 | ≥ 2GB | 单图处理峰值约数百 MB；并发图数默认 2×CPU 核 |
| 端口 | 8200（后端，仅本机）/ 443、80（Nginx） | 可经 `PT_PORT` 修改 |

## 3. 首次部署步骤

### 3.1 获取代码与初始化

```bash
# 假设部署目录为 /opt/pattern-tool
cd /opt/pattern-tool

# 一键初始化：创建 .venv、装钉定版本依赖、执行 opencv headless 修复、生成 .env
./start.sh init
```

`start.sh init` 自动完成：

1. 用 `python3`（3.11/3.12，可用 `PYTHON_BIN=` 覆盖）创建 `.venv/`；
2. 按 `requirements.txt` 钉定版本安装依赖；
3. **opencv headless 修复**：`rapidocr-onnxruntime` 会拉入非 headless 的 `opencv-python`（5.x），脚本检测到即卸载并 `--force-reinstall opencv-python-headless==4.14.0.94`（跳过此步在 Linux 上会报 `libGL.so.1` 缺失）；
4. 若 `.env` 缺失则从 `.env.example` 复制模板。

### 3.2 配置 .env

```bash
vim .env
```

生产必须检查的键（全部键名与默认值见 `.env.example`，与 `src/core/config.py` 字段一一对应）：

| 键 | 生产建议 | 说明 |
|---|---|---|
| `PT_PORT` | `8200` | 与 Nginx `proxy_pass` 保持一致 |
| `PT_DATA_DIR` | `data`（默认，相对项目根） | 磁盘紧张可指向独立数据盘绝对路径 |
| `PT_WM_API_ENABLED` | 按需 `true` | 开启远程模型档需同步填 `PT_WM_API_KEY` 与 `PT_WM_API_SUBMIT_URL` |
| `PT_WM_API_KEY` | 绝不入库不入日志 | 只存在于服务端 `.env`，`.gitignore` 已排除 |

优先级：真实环境变量 > `.env` > `config.py` 默认值。systemd 部署用 `EnvironmentFile=` 指向同一份 `.env`（见 4 节）。

### 3.3 验证启动

```bash
./start.sh run
# 另开终端冒烟：
curl -s http://127.0.0.1:8200/api/meta | head -c 200   # 返回 JSON 即通
curl -s -o /dev/null -w '%{http_code}\n' http://127.0.0.1:8200/   # 200
```

确认无误后 `Ctrl+C` 停掉，转入 systemd 常驻。

## 4. 生产进程管理（systemd）

`/etc/systemd/system/pattern-tool.service`：

```ini
[Unit]
Description=pattern-tool (pt-web) FastAPI service
After=network.target

[Service]
Type=simple
User=www-data
Group=www-data
WorkingDirectory=/opt/pattern-tool
# 与本地开发同构：直接复用 start.sh（内部 exec 到 uvicorn，worker=1）
ExecStart=/opt/pattern-tool/start.sh run
# 生产经 EnvironmentFile 注入与 .env 同构的文件（优先级高于 .env）
EnvironmentFile=/opt/pattern-tool/.env
Restart=on-failure
RestartSec=3

# 加固
NoNewPrivileges=true
PrivateTmp=true
ProtectSystem=full
ReadWritePaths=/opt/pattern-tool/data

[Install]
WantedBy=multi-user.target
```

```bash
# data 目录归属（服务以 www-data 跑时需要写权限）
sudo chown -R www-data:www-data /opt/pattern-tool/data

sudo systemctl daemon-reload
sudo systemctl enable --now pattern-tool
sudo systemctl status pattern-tool      # Active: active (running)
journalctl -u pattern-tool -f           # 实时日志（uvicorn access log + 应用 INFO）
```

> 手动启停也可用 `./start.sh run`（前台）——脚本内 `exec` 替换为 uvicorn 进程，信号直通，`Ctrl+C` / `systemctl stop` 均可优雅退出（lifespan 停 TTL 清理线程与管线执行器）。

## 5. Nginx 反代

三条固定口径（技术方案 7.1）：`client_max_body_size 150MB`、`proxy_request_buffering on`（默认值，吸收慢客户端上传）、`limit_req`（叠加应用层 429）。

`/etc/nginx/sites-available/pattern-tool.conf`：

```nginx
# 每 IP 限流：10r/s，突发 20 排队（应用层还有同 IP ≤3 并发批次的 429 闸）
limit_req_zone $binary_remote_addr zone=pt_limit:10m rate=10r/s;

server {
    listen 80;
    server_name your-domain.example;
    return 301 https://$host$request_uri;
}

server {
    listen 443 ssl;
    http2 on;
    server_name your-domain.example;

    ssl_certificate     /etc/letsencrypt/live/your-domain.example/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/your-domain.example/privkey.pem;

    # 口径 1：批上限 9×15MB + 表单开销
    client_max_body_size 150M;

    # 口径 2：显式声明（nginx 默认即 on）——上传字节由 nginx 吸收后再转后端
    proxy_request_buffering on;

    location / {
        # 口径 3：限流（只打 API 会更精准，静态资源放行走限流也够用）
        limit_req zone=pt_limit burst=20 nodelay;

        proxy_pass http://127.0.0.1:8200;
        proxy_http_version 1.1;

        # 应用层同 IP 限流依赖 X-Forwarded-For 首段（src/app/api.py get_client_ip）
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header Host $host;

        proxy_read_timeout 120s;   # 单图处理 ≤60s，留裕量
    }
}
```

```bash
sudo ln -s /etc/nginx/sites-available/pattern-tool.conf /etc/nginx/sites-enabled/
sudo nginx -t && sudo systemctl reload nginx
```

**X-Forwarded-For 必须设置**：后端限流取该头首段；缺失时所有请求的 IP 都是 127.0.0.1，会错误共享同一个限流桶。

## 6. HTTPS 证书（certbot）

```bash
sudo apt install certbot python3-certbot-nginx
sudo certbot --nginx -d your-domain.example    # 首签 + 自动改写 nginx 配置
sudo systemctl list-timers | grep certbot      # 确认定时续期存在
sudo certbot renew --dry-run                   # 续期演练
```

## 7. 部署验收清单

- [ ] `./start.sh check` 通过（Python 3.11/3.12、应用可导入、端口解析正确）
- [ ] `systemctl status pattern-tool` 为 active，重启机器后自启
- [ ] `curl http://127.0.0.1:8200/api/meta` 返回 JSON（后端通）
- [ ] 浏览器经 `https://your-domain.example` 打开首页并完成一次「上传 → 处理 → 下载」全流程
- [ ] `journalctl -u pattern-tool` 无 `libGL` / `ImportError`（headless 修复生效）
- [ ] 上传 9×15MB 批次不被 Nginx 413 拦截
- [ ] `data/jobs/` 有批次目录，且 24h 后被 TTL 清理器清空（可把 `PT_JOB_TTL_HOURS` 临时调小验证）
- [ ] `.env` 权限 600，未入 git（`git ls-files | grep -F '.env'` 为空）

## 8. 运维要点

| 场景 | 操作 |
|---|---|
| 依赖升级 | 改 `requirements.txt` → `./start.sh init` → `systemctl restart pattern-tool` |
| 改配置 | 编辑 `.env` → `systemctl restart pattern-tool` |
| 看日志 | `journalctl -u pattern-tool -f`；日志不含图片内容与密钥（6 节观测口径） |
| 磁盘告警 | 用量 > 70% 先查 `data/jobs/` 是否异常堆积（TTL 清理器每小时扫 + 启动先扫一次） |
| 数据清理 | 无需手动：批次 TTL 24h；紧急情况停服后删 `data/jobs/{job_id}/` 并重启 |

## 9. 常见问题

| 现象 | 原因与处理 |
|---|---|
| 启动报 `libGL.so.1: cannot open shared object file` | 装了非 headless 的 opencv-python。重跑 `./start.sh init`（自动修复），或手动 `pip uninstall opencv-python && pip install --force-reinstall opencv-python-headless==4.14.0.94` |
| `address already in use`（:8200） | 已有实例在跑：`lsof -nP -iTCP:8200 -sTCP:LISTEN` 找到旧进程停掉，或改 `PT_PORT` |
| 所有人同时被 429 | Nginx 未传 `X-Forwarded-For`，限流桶共享。按 5 节补 `proxy_set_header` |
| 上传大图 413 | Nginx `client_max_body_size` 未到 150M。按 5 节核对 |
| rapidocr 首图慢 | 首次加载 ONNX 模型，属正常；后续图走常驻内存 |
| 想加 GPU（LaMa） | 只替换 `WatermarkStep` 实现，契约与部署不变（技术方案 7.1 预留） |
