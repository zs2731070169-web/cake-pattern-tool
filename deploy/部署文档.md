# pattern-tool 部署文档（Docker Compose + Nginx 网关）

> 部署形态：Docker Compose 双容器——**nginx 网关**（80/443，域名 + HTTPS）反代
> **pt-web**（uvicorn worker=1，容器内 8200，不暴露宿主端口）。单实例即可承接目标
> 负载（技术方案 1.5 容量测算：高峰 1200–1600 图/天）。
> 依据：《修图工具最小技术方案.md》6 节（单写者/并发）、7 章与 7.1 节（部署硬约束）。
> 旧版裸机 systemd 方案见 git 历史（`git log -- deploy/部署文档.md`）。

## 1. 架构与数据流

```
用户浏览器/手机
   │  HTTPS 443（域名）
   ▼
nginx 网关容器（证书终止 + 上传缓冲 + 80→443 跳转）
   │  内部网络 HTTP pt-web:8200
   ▼
pt-web 容器（FastAPI + uvicorn worker=1）
   ├── /api/*   业务接口（建批/轮询/下载/meta）
   ├── /        静态前端（web/，同进程同源挂载）
   ├── 卷 app-data:/app/data   SQLite(WAL) + 批次图 + 缓存 + 日志
   └── 出网     百炼 qwen-vl/qwen-image · 石榴去水印 · 佐糖 scale-pro
```

关键口径（红线，见 7 节详述）：**worker=1 不可改**；**容器内端口固定 8200**；
**不在容器里跑 `start.sh`**（那是本地调试脚本，每次启动清空 `data/`）。

## 2. deploy 目录清单

| 文件 | 作用 |
|---|---|
| `Dockerfile` | 生产镜像（python:3.12-slim + 依赖 + u2netp 模型预下载） |
| `docker-compose.yml` | pt-web + nginx 编排（健康检查、数据卷、依赖顺序） |
| `deploy.sh` | **一键部署/升级/续期/状态脚本**（本文档流程的自动化封装，推荐入口） |
| `nginx/conf.d/pattern-tool.conf` | 网关生产配置（HTTPS，需先有证书） |
| `nginx/pattern-tool.http.conf.example` | 网关 HTTP 联调版（签证书前的临时形态） |
| `部署文档.md` | 本文档 |
| （仓库根）`.dockerignore` | 构建上下文裁剪——**`.env` 绝不进镜像**，运行时由 compose 注入 |

## 3. 前置条件

| 项 | 要求 | 说明 |
|---|---|---|
| Docker | Engine ≥ 24 + Compose v2 | `docker compose version` 可查 |
| 服务器 | Linux x86_64/arm64，≥2GB 内存，磁盘 ≥50GB | 瞬时驻留 12–24GB，TTL 24h 兜底 |
| 网络 | 80/443 入站放行；服务器可出网（三家外部 API） | pt-web 容器需访问 dashscope/shiliuai/aoscdn |
| 域名 | DNS A 记录指向服务器公网 IP | 签证书与访问都依赖 |
| `.env` | 仓库根放好（`cp .env.example .env` 后填 key） | 与本地开发同源；密钥只在此处，绝不入库/进镜像 |

## 4. 首次部署

### 4.0 一键路径（推荐）

```bash
cd deploy
./deploy.sh -d 你的域名 -m 你的邮箱    # 无证书自动签发；已有证书直接 HTTPS；无域名则裸跑 HTTP 联调
```

脚本自动完成本文档 4.1–4.5 的全部步骤（前置检查 → 起栈 → 健康等待 → 证书
签发/切换 → 冒烟），并内置 `upgrade`（滚动重建）/ `renew-cert`（续期）/
`status`（状态+冒烟）子命令。以下 4.1–4.5 为手动等价流程（排障或自定义时用）。

### 4.1 手动流程

以下命令均在**服务器仓库根**执行（`cd /opt/pattern-tool` 之类）。

### 4.1 准备 .env

```bash
cp .env.example .env
vim .env        # 必填：PT_WM_PRECHECK_KEY / PT_SHILIU_API_KEY / PT_PICWISH_API_KEY / PT_FILL_GEN_KEY
```

未配 key 的步骤零误伤跳过（服务能起，对应功能降级）；`.env` 其余键保持默认即可。

### 4.2 联调起栈（HTTP，签证书前）

```bash
cd deploy
cp nginx/pattern-tool.http.conf.example nginx/conf.d/pattern-tool.conf
sed -i 's/pattern\.example\.com/你的域名或服务器IP/' nginx/conf.d/pattern-tool.conf
docker compose up -d --build
```

冒烟（应返回 JSON）：

```bash
curl -s http://你的域名或IP/api/meta | head -c 200
docker compose ps          # 两个服务均 healthy/running
```

打开 `http://你的域名` 传一张图走全流程，确认外呼 key 有效。

### 4.3 签发 HTTPS 证书（certbot standalone）

先停网关释放 80 端口，签发到宿主机 `/etc/letsencrypt`：

```bash
cd deploy && docker compose stop nginx
docker run --rm -p 80:80 certbot/certbot certonly --standalone \
  -d 你的域名 --agree-tos -m 你的邮箱
docker compose start nginx   # 此刻还是 HTTP conf，无影响
```

### 4.4 切生产配置（HTTPS）

仓库里 `nginx/conf.d/pattern-tool.conf` 本就是生产版（HTTPS）；4.2 联调时被
HTTP 版覆盖了，恢复并替换域名：

```bash
git checkout -- nginx/conf.d/pattern-tool.conf     # 恢复生产版 conf
sed -i 's/pattern\.example\.com/你的域名/g' nginx/conf.d/pattern-tool.conf
docker compose exec nginx nginx -t                 # 配置语法校验
docker compose up -d nginx                         # 重建网关挂载新 conf
```

### 4.5 验收清单

| 检查 | 期望 |
|---|---|
| `curl -I http://你的域名` | 301 → https |
| `curl -s https://你的域名/api/meta` | 200 + JSON |
| 浏览器域名访问 | 锁标志正常，前端可用 |
| 传 9 张图建批 | 受理 200，轮询逐图 completed |
| `docker compose ps` | pt-web healthy、nginx running |
| 超大文件（>300MB）上传 | nginx 413（上限前置放行口径） |

## 5. 日常运维

```bash
cd deploy

# 启停
docker compose up -d            # 全栈起
docker compose stop             # 全栈停（数据卷保留）
docker compose down             # 删容器（数据卷保留；down -v 才删数据，慎用）

# 日志
docker compose logs -f pt-web      # 应用控制台（INFO）
docker compose exec pt-web tail -f /app/data/logs/app.log   # 文件通道（DEBUG，排障主径）

# 升级（拉代码后）
docker compose build pt-web && docker compose up -d pt-web     # 滚动重建 pt-web，nginx 不动
# 数据卷跨版本保留；db/schema.sql 幂等建表，加列有防御迁移（started_at 先例）

# 数据备份（SQLite + 批次图；tar 到宿主当前目录）
docker compose exec pt-web tar czf - /app/data > ../pattern-data-$(date +%F).tgz

# 证书续期（standalone 方式，约 60–80 天一次，停网关约 10 秒）
docker compose stop nginx
docker run --rm -p 80:80 certbot/certbot renew
docker compose start nginx
```

## 6. 配置说明

- **`.env` 优先级**：真实环境变量 > `.env` > 代码默认值（pydantic-settings）。
  compose 的 `env_file: ../.env` 即真实环境变量注入。
- **容器内固定 8200**：`PT_PORT` 在 Docker 形态下不要改（改了需同步 Dockerfile
  的 EXPOSE/CMD、compose 的 healthcheck、nginx 的 proxy_pass 四处）。
- **`PT_MAX_CONCURRENT_PROCESSING`**：同时在处理的图数（默认 0=自动 2×CPU 核）。
  外呼等待占单图耗时 85%，小核 VM 建议 9–16 保证 9 图批全并行。
- **`PT_DATA_DIR`**：保持默认 `data`（容器内 /app/data，已挂卷）。磁盘紧张时
  可改 compose 卷为宿主 bind mount 指向数据盘。

## 7. 红线与硬前提（翻车预防）

1. **worker=1**：SQLite 单写者 + 进程内单例（配置/连接池/线程池）都以单进程为
   前提——Dockerfile 的 CMD 没有也不允许加 `--workers N`；不要为"提速"改
   compose 的 `replicas`（同因）。
2. **不在容器里跑 `start.sh`**：它每次启动清空 `data/` 并杀 8200 端口进程，
   是本地调试口径；容器生命周期内数据靠 TTL 每小时清理 + 重启恢复兜底。
3. **密钥只走 `.env`**：`.dockerignore` 已排除 `.env`（密钥绝不进镜像层）；
   `.gitignore` 同样排除（绝不入库）。日志/前端/错误信息无 key（config 口径）。
4. **不要用 `down -v`**：会删数据卷（SQLite + 在途批次）。清数据的正当途径是
   TTL（24h 自动）。
5. **uvicorn 重启语义**：容器重启时悬挂 processing/queued 图自动置 failed
   （"服务重启中断，请重新提交"），不留死状态——升级窗口选在业务低谷。

## 8. 常见问题

| 症状 | 原因与处理 |
|---|---|
| nginx 502 | pt-web 未就绪（`docker compose ps` 看 health）或刚重启——网关会随 healthcheck 自动恢复；持续 502 看 `docker compose logs pt-web` |
| 上传 413 | 超过 `client_max_body_size 300m`（单批 9 图+9 原图上限）；正常业务（9×15MB×2）不会触达 |
| 首次描边慢几秒 | rembg u2netp 模型已在镜像预下载，慢的是首次 onnxruntime 预热，仅一次 |
| 证书路径报错 | conf 里域名占位没替换完全（fullchain/privkey 路径含域名）——`grep example nginx/conf.d/` 应为空 |
| 想看外呼链路明细 | `docker compose exec pt-web grep 'watermark\|fill' /app/data/logs/app.log`（DEBUG 通道全量落盘） |
